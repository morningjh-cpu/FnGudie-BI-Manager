# 15 브랜드 사이트 콘텐츠 크리틱 (2026-10-29)

## 요청
- 디자인 크리틱처럼 이 웹페이지의 콘텐츠 크리틱을 한다.
- 전문가 3인이 브레인스토밍과 크리틱을 한다. 셋 다 경력 10년 이상이다.
  - 브랜드 전략가
  - 시니어 카피라이터
  - UX 콘텐츠 전문가
- 세 사람 모두 문장을 직접 고칠 수 있다.
- 최종 의견은 각자 중심을 둔다.
  - 브랜드 전략가: 방향성
  - 카피라이터: 표현력
  - UX 콘텐츠 전문가: 사용자 이해도
- 계획을 보여 드린 뒤 "진행"으로 시작했다.

## 범위와 방법
- 대상: index.html 의 모든 글
  - 메뉴, 제목, 본문, 안내 상자, 버튼, 표 머리, 그림 설명
  - 스크립트가 만드는 로고타입 그룹 설명
- 화면 캡처 8장: `out/content-critique/img/page-*.png`
  - 대상 화면: 홈, 서체 소개, 폰트 업데이트, 디자인 크리틱, B2B 그룹, 회사 CI, 다운로드, 사용 규칙
- 전문가 3인은 AI가 관점을 나눠 맡았다. 실제 전문가 검수를 대신하지 않는다.
- 사이트 문장은 고치지 않았다. 수정안만 제시했다.

## 1. 브레인스토밍 기록

### 이 사이트는 무엇을 약속하는가
- **전략가**
  - 홈 첫 문장은 "자산 관리 서비스입니다"라는 소개문이다.
  - 사이트가 지켜야 할 약속은 하나다. "여기 있는 파일이 언제나 최신 공식본이다."
  - 이 약속이 첫 화면 맨 위에 와야 한다.
- **카피**
  - 첫 문장이 두 줄 반이다. "줄이고", "쓰도록 합니다"처럼 운영자 시점이다.
  - 쓰는 사람 시점으로 뒤집으면 짧아진다.
- **UX**
  - 첫 화면에 온 임직원의 할 일은 거의 넷이다: 로고 받기, 서체 받기, 컬러 코드 확인, 써도 되는지 확인.
  - 지금 카드 4개(Typeface·Logotype·Download·Guidelines)는 영어 제목이 먼저 보인다.
  - 할 일 동사(받기·확인)가 약하다.

### 누가 쓰는가
- **UX**
  - 주 사용자는 비디자이너 임직원이다. 영업, 기획, 개발, 마케팅이 해당한다. 디자인 파트는 소수다.
  - 그런데 서체 사양, 폰트 업데이트, 디자인 크리틱은 디자이너용 수치로 가득하다.
    - 예: UPM, tnum, 688→711, Windows 위쪽 높이 870
- **전략가**
  - 크리틱과 업데이트 기록을 공개하는 것 자체는 좋다. 브랜드를 관리하고 있다는 신뢰가 생긴다.
  - 다만 "누구를 위한 기록인지"를 첫 줄에 밝혀야 한다.
- **카피**
  - 사용자에게는 "무엇이 달라졌고, 나는 무엇을 하면 되는지"가 먼저다.
  - 예: "새 파일로 다시 설치하세요"

### 메시지가 서로 부딪히는 곳
- **전략가**
  - 서체 소개는 "키보드로 입력한 FnGuide가 공식 로고와 같은 형태"라고 말한다.
  - 그런데 사용 규칙과 로고 화면은 "로고를 서체로 입력해 대체하지 않는다"고 말한다.
  - 자랑과 금지가 충돌한다. 사용자는 "그럼 입력해도 되나?"로 읽는다.
  - 가장 먼저 정리해야 할 방향 문제다.
- **카피**
  - 자랑은 "로고와 같은 느낌으로 제목을 쓸 수 있다"로 바꾼다.
  - 금지는 "로고 자리에는 원본 파일"로 짝을 맞추면 둘 다 살아난다.

### 빠진 것
- **UX: 문의처**
  - "디자인 파트를 통해 요청"이 세 번 나오지만 연락 방법이 어디에도 없다.
  - 개인 이름 대신 팀 메일이나 그룹웨어 경로를 적는다(개인정보 노출 방지).
- **UX: 한글 서체**
  - "한글은 기존 지정 서체"라고만 한다. 어떤 서체인지 이름이 없다.
- **전략가: 기대 효과**
  - 홈의 "기대 효과" 4개는 기획 보고서 언어다. 사용자에게 행동을 주지 않는다.
- **카피: 임시 안내**
  - 헤더의 "콘텐츠가 정리되면 현재의 AI 디자인은 업데이트 될 예정입니다."는 임시 안내다.
  - 정식 공개 전에 지워야 한다.

### 용어
- **카피**
  - 같은 것을 여러 이름으로 부른다.
    - 로고 / 로고타입 / BI / 브랜드 로고 / 개선 로고
    - 흰색 판 / 흰색
    - 단도 색상 / 단색 파일
  - 용어표를 하나 정해 통일해야 한다.
- **UX**
  - 메뉴 이름과 화면 제목이 다르다.
    - 로고타입 다운로드 ↔ Assets
    - CI/BI 디자인 운영 ↔ CI/BI Management
  - 영어 제목은 브랜드 스타일로 두되, 메뉴의 한국어 이름을 작은 제목(eyebrow)에 그대로 쓰면 연결된다.
- **전략가**
  - "디자인 운영"은 내부 업무명이다.
  - 홈 메뉴는 "브랜드 개요"처럼 사용자가 기대하는 말이 낫다.
  - 이 부분은 의견이 갈렸다. 카피는 "홈"을 제안했다.

## 2. 화면별 크리틱 (등급, 지금 → 수정안, 제안자)

### 공통 / 헤더

  - 남겨야 한다면 UX 안: "시험 운영 중입니다. 의견은 디자인 파트로 보내 주세요."

## 4. 최종 의견
- **브랜드 전략가 (방향성)**
  - 사이트의 약속을 "이곳 파일이 언제나 최신 공식본"으로 모은다.
  - 서체 소개의 자랑과 사용 규칙의 금지를 한 방향으로 맞춘다. 이것이 1순위다.
  - 내부 기록(크리틱·업데이트 수치)과 사용자 안내를 구분해 첫 줄에서 대상을 밝힌다.
  - 기대 효과처럼 보고서에서 옮겨 온 말은 덜어 낸다.
  - CI 컨셉 문장("금융시장을 바라보는 새로운 창")을 브랜드 이야기의 중심으로 쓴다.
- **시니어 카피라이터 (표현력)**
  - 운영자 시점("~하도록 합니다")을 사용자 시점("~하세요")으로 바꾼다.
  - 추상 명사 묶음을 구체적인 그림으로 바꾼다.
    - 예: "일관성·유연성·효율성" → "컬러만 봐도 어느 사업인지"
  - 용어표를 정한다.
    - 로고/로고타입
    - 흰색 버전
    - 단색
    - 고정폭 숫자
  - 영어 제목 + 한국어 작은 제목 짝을 모든 화면에 같은 방식으로 쓴다.
- **UX 콘텐츠 전문가 (사용자 이해도)**
  - 첫 화면을 할 일 4개 중심으로 바꾼다.
  - 문의처와 한글 서체 이름처럼 다음 행동에 필요한 정보를 채운다.
  - 수치는 뜻을 붙이거나 디자이너용으로 접는다.
  - 업데이트 소식은 언제나 "그래서 나는 무엇을 하면 되는지"로 끝낸다.
  - 다운로드 화면에서 서체도 찾을 수 있게 한다.
