  - 개선안 보고서 "수정 후" 윤곽(after.py·symbols.py·one_base.py·tail_l.py)만 바꾼다.
  - 바뀐 글자의 겹친 획은 skia-pathops 로 합쳤다(이번에 설치).
- 확인용 다시 만들기
  - `--control` 로 아무것도 바꾸지 않고 다시 만들어 v1.200 과 비교했다.
  - 영문·숫자 두 글자 쌍 전체와 문장 몇 개의 글자 위치가 모두 같았다.
  - 확인 뒤 control 폴더는 지웠다. 다시 만들 수 있는 파일이다.
- 바뀐 것
  - ① C·G 위 711
  - ② v·w·x·y 500
  - ③ o·c·e 위 512
  - ④ ft·fj 합자
    - 오른쪽 커닝은 t·j 의 개별 쌍을 복사했다. 왼쪽은 f 묶음(@L_f)에 넣었다.
    - ty·rv 는 +20 을 0 으로 바꿨다. 기존 줄을 고쳤다. 같은 쌍을 다시 적으면 feaLib 이 뒤엣것을 무시한다.
  - ⑤ Windows 위쪽 높이 870, Regular 표시(fsSelection 0x40)
  - ⑥ 1 은 폭 474, 받침 너비 420. l 은 폭 328, 꼬리 끝 296.
  - ⑨ 금융 기호
    - 추가: ₩(uni20A9) −(minus) ±(plusminus) ×(multiply) ·(periodcentered)
    - − ± × 는 + 와 같은 커닝 묶음에 넣었다. ₩ 와 · 는 커닝 없음.
  - ⑨ 고정폭 숫자: tnum 기능을 넣었다. 0~9 와 + − ± 가 .tf 글자로 바뀌고 폭은 600 이다.
  - 버전 표시는 Version 1.3, head 1.3 이다. 글자 수는 129개다(대체 글자 포함).
- 확인

  - 새 l·1·ft·fj 와 이웃 글자의 닿음을 검사했다.
    - 닿는 쌍은 없다.
    - 가장 가까운 쌍은 ty·rv·fty 로, 간격이 8 이다. 보정을 0 으로 한 결과다.

## 고침: L·E 왼쪽 아래 (2026-10-29, 사용자 지적)
- 증상: v1.3 에서 L·E 의 왼쪽 아래(기둥과 아래 가로획이 만나는 곳)가 뚫려 보였다.
- 원인
  - L·E 는 기둥 조각과 아래 가로획 조각이 겹친 두 윤곽으로 되어 있다.
  - build_v13.py 의 윤곽 방향 맞추기가 가로획 조각의 시작점(132,63)을 기둥 "안"으로 보고 구멍 방향으로 뒤집었다.
  - 그 결과 겹친 부분이 빠졌다. v1.200 은 SVG 조각 묶음 단위로 판단해서 이 문제가 없었다.
- 고침
  - 바꾸지 않은 글자는 v1.200 OTF 의 윤곽 방향을 그대로 쓴다. TTF 는 모두 뒤집기만 한다.
  - 방향을 판단하는 것은 pathops 로 겹침을 합친 "바꾼 글자"만이다.
- 확인
  - 모든 글자를 v1.200 과 화면 점 단위로 비교했다.
    - OTF: 의도한 11자(1 C G c e l o v w x y)만 다르다.
    - TTF: v1.200 TTF 와 OTF 사이의 차이와 같은 수준이다. 두 형식의 곡선 표현 차이다.
  - --control 다시 만들기로 v1.200 과 쌍 위치·폭이 모두 같음을 다시 확인했다.
  - 그림: out/font-update/v1.3/check-LE.png
