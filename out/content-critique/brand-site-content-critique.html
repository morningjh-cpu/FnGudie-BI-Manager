전문가 3인은 AI가 각 분야의 관점을 나눠 맡아 쓴 것으로, 실제 전문가의 검수를 대신하지 않습니다. 세 사람 모두 문장을 직접 고쳐 썼고, 최종 의견은 각자 맡은 기준(방향성·표현력·사용자 이해도)으로 냈습니다. 사이트 문장은 아직 고치지 않았습니다. 이 문서의 수정안 가운데 반영할 것을 골라 주세요.

1. 전문가 총평

브랜드 전략가 · 방향성

사이트가 지켜야 할 약속은 "이곳 파일이 언제나 최신 공식본"입니다. 그런데 서체 소개의 자랑("입력하면 로고와 같다")과 사용 규칙의 금지("로고를 서체로 입력하지 않는다")가 부딪힙니다. 이것부터 한 방향으로 맞춰야 합니다.

시니어 카피라이터 · 표현력

문장이 운영자 시점("~하도록 합니다")과 추상 명사("일관성·유연성·효율성")에 기대고 있습니다. 사용자 시점의 짧은 문장과 구체적인 그림으로 바꾸고, 같은 것을 부르는 이름을 하나로 통일해야 합니다.

UX 콘텐츠 전문가 · 사용자 이해도

주 사용자는 비디자이너 임직원인데, 디자이너용 수치(UPM, tnum, 688→711)가 앞에 나옵니다. 첫 화면은 할 일 4개 중심으로, 수치는 뜻을 붙이거나 접고, 문의처처럼 다음 행동에 필요한 정보를 채워야 합니다.

2. 브레인스토밍

이 사이트는 무엇을 약속하는가

전략가 — 홈 첫 문장이 "자산 관리 서비스입니다"라는 소개문입니다. 약속은 하나, "여기 있는 파일이 언제나 최신 공식본"이고, 이것이 첫 화면 맨 위에 와야 합니다.
카피 — 첫 문장이 두 줄 반이고 "줄이고", "쓰도록 합니다"처럼 운영자 시점입니다. 쓰는 사람 시점으로 뒤집으면 짧아집니다.
UX — 첫 화면에 온 임직원의 할 일은 로고 받기, 서체 받기, 컬러 코드 확인, 써도 되는지 확인 네 가지입니다. 지금 카드 4개는 영어 제목이 먼저 보이고 할 일 동사가 약합니다.

누가 쓰는가

UX — 주 사용자는 영업·기획·개발·마케팅 같은 비디자이너 임직원입니다. 그런데 서체 사양, 폰트 업데이트, 디자인 크리틱은 디자이너용 수치로 가득합니다.
전략가 — 크리틱과 업데이트 기록을 공개하는 것은 "브랜드를 관리하고 있다"는 신뢰를 줍니다. 다만 누구를 위한 기록인지 첫 줄에 밝혀야 합니다.
카피 — 사용자에게는 "무엇이 달라졌고, 나는 무엇을 하면 되는지"가 먼저입니다. 예: "새 파일로 다시 설치하세요."

메시지가 서로 부딪히는 곳

전략가 — 서체 소개는 "키보드로 입력한 FnGuide가 공식 로고와 같은 형태"라고 하고, 사용 규칙과 로고 화면은 "로고를 서체로 입력해 대체하지 않는다"고 합니다. 사용자는 "그럼 입력해도 되나?"로 읽습니다.
카피 — 자랑은 "로고와 같은 인상으로 제목을 쓸 수 있다"로, 금지는 "로고 자리에는 원본 파일"로 짝을 맞추면 둘 다 삽니다.
합의: 가장 먼저 고칠 방향 문제로 정했습니다(수정 필요 ③).

빠진 것과 덜어 낼 것

UX — "디자인 파트를 통해 요청"이 세 번 나오지만 연락 방법이 없습니다. 개인 이름 대신 팀 메일이나 그룹웨어 경로를 적어야 합니다. "한글은 기존 지정 서체"도 서체 이름이 없습니다.
전략가 — 홈의 "기대 효과" 4개는 기획 보고서의 언어라 사용자에게 할 일을 주지 않습니다.
카피 — 헤더의 "콘텐츠가 정리되면 현재의 AI 디자인은 업데이트 될 예정입니다."는 임시 안내라 정식 공개 전에 지워야 합니다.

용어와 이름

카피 — 같은 것을 여러 이름으로 부릅니다: 로고 / 로고타입 / BI / 브랜드 로고 / 개선 로고, 흰색 판 / 흰색, 단도 색상 / 단색 파일.
UX — 메뉴 이름과 화면 제목이 다릅니다(로고타입 다운로드 ↔ Assets, CI/BI 디자인 운영 ↔ CI/BI Management). 영어 제목은 두되, 작은 제목에 메뉴의 한국어 이름을 그대로 쓰면 연결됩니다.
전략가 — "디자인 운영"은 내부 업무명입니다. 홈 메뉴는 "브랜드 개요"가 낫습니다. (카피는 "홈"을 제안 — 의견 갈림)

4. 최종 의견

브랜드 전략가 · 방향성

① 사이트의 약속을 "이곳 파일이 언제나 최신 공식본"으로 모읍니다. ② 서체의 자랑과 로고 사용 금지를 한 방향으로 맞추는 것이 1순위입니다. ③ 내부 기록(크리틱·업데이트 수치)과 사용자 안내를 구분해, 화면 첫 줄에서 대상을 밝힙니다. ④ "기대 효과"처럼 보고서에서 옮겨 온 말은 덜어 내고, CI 컨셉 문장("금융시장을 바라보는 새로운 창")을 브랜드 이야기의 중심으로 씁니다.

시니어 카피라이터 · 표현력

① 운영자 시점("~하도록 합니다")을 사용자 시점("~하세요")으로 바꿉니다. ② 추상 명사 묶음을 구체적인 그림으로 바꿉니다("일관성·유연성·효율성" → "컬러만 봐도 어느 사업인지"). ③ 용어표를 정합니다: 로고/로고타입, 흰색 버전, 단색, 고정폭 숫자. ④ 영어 제목 + 한국어 작은 제목 짝을 모든 화면에 같은 방식으로 씁니다.

UX 콘텐츠 전문가 · 사용자 이해도

① 첫 화면을 할 일 4개(서체 받기·로고 받기·컬러 확인·써도 되는지 확인) 중심으로 바꿉니다. ② 문의처와 한글 서체 이름처럼 다음 행동에 필요한 정보를 채웁니다. ③ 숫자는 뜻을 붙이거나 디자이너용으로 접습니다. ④ 업데이트 소식은 늘 "그래서 나는 무엇을 하면 되는지"로 끝냅니다. ⑤ 다운로드 화면에서 서체도 찾을 수 있게 합니다.

5. 결정해 주실 것

  1. 문의처 표기 방법 — 팀 메일·그룹웨어 경로 등 (개인 이름은 넣지 않음)
  2. 한글 지정 서체 이름
  3. 메뉴 이름 방향 — 전략가안 / 카피안 / UX안
  4. 홈 "기대 효과" — 삭제 / "이 사이트에서 할 수 있는 일"로 대체
  5. 수정안 중 사이트에 반영할 범위 — 수정 필요 6건만 / 개선 권장까지 전부 / 골라서

6. 방법과 한계

  • index.html의 모든 글(스크립트가 만드는 로고타입 그룹 설명 포함)을 화면별로 모으고, 화면 캡처 8장(img/page-*.png)으로 글의 위치와 읽는 순서를 확인했습니다.
  • 실제 사용자 조사(설문·사용성 시험)는 하지 않았습니다. 사용자 이해도는 전문가 관점의 추정입니다.
